# Cover, caption and visibility

## Cover

Base the cover title on the final opening's actual content and strongest supported promise. Retain the user's exact preferred wording when provided. Prefer short, readable text over a full sentence. Avoid unsupported universal thresholds, guaranteed outcomes and causality claims based only on two examples.

Honor the user's scene preference. If they reject cutouts/background removal, preserve the real scene and do not deliver an isolated presenter on a generic backdrop. Without a preference, use a real still as the starting point. Inspect any local reference image before editing with an image tool. Preserve identity, important background context and exact supplied data. Save generated assets into the task's output folder, not only a tool's temporary/default directory. Keep tool/prompt provenance if relevant to that tool's workflow.

An engagement strip and skip-rate chart answer different questions. Label them accurately; do not substitute likes/comments for retention evidence. Computed ratios must use the same metric in both examples, show appropriate rounding, and be described as comparisons rather than promised improvement.

## Safe-zone procedure

1. If the user supplies a guide, inspect it and map its boundaries to the actual video/cover dimensions. Follow the usable region, including right-side interaction controls and rounded/stepped boundaries. Keep the guide out of final media.
2. If no guide exists, use a conservative **working assumption**, not a claimed official Instagram specification: keep essential text approximately within x=10–82%, y=15–75% of a 9:16 frame, then adjust for actual UI/crop context. The photographic background may bleed to edges. For other aspect ratios, inspect the intended display instead of reusing these numbers blindly.
3. Reels UI clearance and profile-grid cropping are different. If grid/feed visibility is requested, inspect the current applicable crop or supplied preview; do not assume a permanent platform crop. Put the essential headline in the intersection of relevant regions when possible.
4. Test the widest text, multiline bounds, shadow/glow and maximum animation scale/overshoot. Check moving people/graphics can cross or occlude text even when its box stays within the safe zone.
5. Verify on the actual exported cover and video at readable size. Distinguish geometrically inside the zone from not obscuring a face, product, result or source caption. Fix both.

## Caption

Write ready-to-post copy in the requested language/register, aligned to the final video and cover. Open with a concrete pain point, question or supported result. Add context/usefulness beyond copying every subtitle, then one appropriate CTA. Use only verified handles, credits, numbers and links; omit unknown handles. Keep hashtags relevant and modest. Do not promise the new edit will outperform the original.

Provide copyable text and, for a production package, a plain UTF-8 text file. Creating a caption does not authorize posting it.

## Final QA evidence

Retain a lightweight note with selected source/project version, key edits, checked timestamps, safe-zone basis, exported duration/dimensions, data transcription checks and audio-check status. Mark unavailable checks honestly. If publishing multiple variants, make file/project names unambiguous so a rejected draft is not mistaken for the final.
