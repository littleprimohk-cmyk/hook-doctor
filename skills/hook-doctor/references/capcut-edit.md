# CapCut production and recovery

## Preflight

Confirm exact project and latest content from observed UI. A user's manual edits outrank an earlier assistant export. Use supplied previous footage as a style reference, not as a replacement source. Discover actual control capabilities and read their instructions; never describe a filesystem render as CapCut work.

Duplicate the project using its native UI and name the variant clearly, such as `<project> Hook V2`. Preserve existing references/assets. Read available menus before guessing actions. Re-observe after state-changing actions; accessibility identifiers and coordinates may change after dialogs or window resizing.

## Build a feasible cut

Write source in/out and destination timing for affected segments. Keep spoken sentences coherent. Preserve sync of voice, captions, B-roll, sound effects and music. Removing a lead-in may require closing gaps on multiple tracks and adjusting a music entrance.

If moving every track together is cumbersome, a native compound clip/subproject can preserve their alignment and editability. Verify all intended tracks are included, that source duration is retained, and that the variant can still expose individual text/media. Splitting/deleting a compound is not necessarily ripple deletion: check the actual left edge at 00:00:00:00 and total duration.

Use the **actual visual cut** and checked speech onset. Advance frame-by-frame at uncertain boundaries; a transcript timestamp or a previous export may be one or more frames off. Do not leave a flash frame of the old hook.

## Improve typography without hiding content

Edit existing native captions/graphic layers, including font, size, color, outline/shadow, placement and animation. Shorten text or split lines before solving width problems with a large backdrop. Give one keyword emphasis rather than making every element louder.

If a panel obstructs content, resize/move/remove that panel itself. When only a flattened file exists, import it into a new native project and use feasible cuts, reframing or small unobtrusive text. Do not pretend burned-in layers are separately editable. If the exact requested repair requires missing original layers, explain that constraint and deliver the best honest alternative.

An on-screen headline can differ from verbatim speech when clearly serving as an editorial headline, but it must not misquote the speaker or distort meaning. Preserve genuine dialogue captions separately when appropriate.

## UI failures

- A clipboard timeout can occur after text was inserted. Inspect the field before retrying to prevent duplication.
- A click can leave a dialog pending; inspect state and use the visible correct button before assuming success.
- If the user changes the app, refresh state before more actions and preserve their changes.
- Confirm every important mutation by timeline/preview state. If repeated attempts cannot identify the correct action, use another supported UI path. Stop risky mutations when state is uncertain; report the exact obstacle without claiming completion.
- Do not solve UI trouble by editing undocumented project JSON or substituting another editing application without the user's agreement.

## Export and verification

Export a new filename through CapCut with suitable source aspect ratio/frame rate and ordinary social-video quality. Preserve color management unless an actual compatibility issue requires an explicit conversion. Avoid premium effects/assets the user cannot export.

Check opening/closing frames, every new cut, each new text animation, and changed overlays in the exported file. Confirm audio exists and timing matches; where playback/audio inspection is unavailable, disclose that rather than claiming a listening check. Read-only local frame extraction and media probing are appropriate for QA.

Leave the saved variant identifiable and return the export path. Do not press social sharing/publish buttons as part of a local export request.
